# La-Proteina

> **状态**：已完成（表征、隐变量维度、采样、数据、结果均已回到一手 PDF 核实；代码 license 与部分训练算力未核实）
> **记录人**：团队共同学习
> **最后更新**：2026-11-10

> 三句话速判：**它把"全原子生成"拆成两段——流匹配只生成 Cα 与每残基 8 维隐变量，VAE 解码器再把隐变量解成 36 个非 Cα 原子与残基类型**；因此它是"部分潜变量"（partially latent），不是"全潜变量"、也不是"32 维"；**它不用外部折叠模型做监督或自洽**（ESMFold 只出现在评测环节），采样是耦合双时间 SDE 的 400 步 Euler–Maruyama。

## 1. 学习背景与目标

### 1.1 为什么学它

- 它是 Proteina（Cα 单点流匹配）的**直接后继**，同一批 NVIDIA 作者，把"只生成一个 Cα 点"推进到"生成全原子 + 序列"。
- 它是本仓库「部分隐变量」这条线的**源头**：RFD4-Proteina 在技术报告里明确写 "extending the partially latent formulation introduced in La-Proteina"，Proteina-Complexa 直接复用它训练好的 VAE。不读它，后两篇的"粒度"字段就没有共同参照。
- 它也是仓库里唯一**被明确记录过填错**的一篇：曾把它的隐变量维度写成 32（那是 RFD4-Proteina 的数字），也曾把"依赖外部折叠模型做监督"记在它名下。本篇的首要任务之一就是给出反向证据。

### 1.3 本次目标

1. 判定表征粒度：它到底"全原子"到什么程度，生成端自由度是多少。
2. 拆开"部分潜变量"：隐变量维度、编码什么、谁解码、为什么必须保留显式 Cα。
3. 核清三处易错点：32 维 / 外部折叠模型监督 / 采样步数与 σ 调度。
4. 补齐训练数据口径与规模分档。
5. 给 VNAR 场景的可用性判断（能做 motif 脚手架吗，能信它的原子精度吗）。

### 1.4 命名与维度的历史混淆（本篇核心订正）

仓库历史上出现过"La-Proteina 用 32 维隐变量"的写法。逐条回查后，**该说法不成立**，三条独立证据：

| 主张 | 证据 | 标记 |
| --- | --- | --- |
| La-Proteina 的隐变量是 **8 维** | 论文 §3.1 原文："8-dimensional per-residue latent variables"，记号 `z ∈ R^{L×8}` | 【核实：PDF 正文】 |
| Proteina **完全没有**隐变量 | Proteina §3.2 的生成变量只有 `x ∈ R^{3L}` 的 Cα 点；全文 `latent` / `decoder` 0 命中 | 【核实：Proteina 全文检索】 |
| 32 维属于 **RFD4-Proteina** | RFD4 技术报告 Table S13 "Latent dimension: 32 per token"；配置 `latent_z_dim: 32` | 【核实：RFD4-Proteina 报告 + 配置】 |

所以三者的正确排列是：**Proteina（无 latent）→ La-Proteina（8 维）→ RFD4-Proteina（32 维 + 内部 reasoning）**。把 8 记成 32，等于把两代之后的设计提前安到源头模型上。

## 2. 核心概念

| 术语 | 本篇含义 |
| --- | --- |
| partially latent | 只有**一部分**自由度进隐空间：Cα 坐标 `x_Cα` 显式建模，其余（侧链原子、残基类型）压进每残基隐变量 `z`。对应模板粒度档位里的"主链显式 + 侧链隐变量"。【核实：§3.1】 |
| `x_Cα` | `R^{L×3}`，每残基一个 Cα 坐标，与 Proteina 的生成变量同一空间。【核实：§3.1】 |
| `x_¬Cα` | `R^{L×36×3}`，Atom37 去掉 Cα 后剩 36 个槽位。Gly 等残基的缺位槽由解码器一起处理。【核实：§3.1】 |
| `z` | `R^{L×8}`，每残基 8 维隐变量。**这是全篇最容易被记错的数字。** 【核实：§3.1】 |
| `s` | `{0..19}^L`，20 类标准残基的身份变量。【核实：§3.1】 |
| VAE 编码器 `q_ψ(z \| x_Cα, x_¬Cα, s)` | 训练时把"完整结构 + 序列"压成 8 维隐变量；只在训练用，推理时不出现。【核实：§3.2.1】 |
| VAE 解码器 `p_φ(x_¬Cα, s \| x_Cα, z)` | 推理时把（Cα, z）解成侧链原子与序列；坐标取均值、序列取 argmax。【核实：§3.4】 |
| denoiser（流匹配主干） | 160M、16 block，同时预测 `x_Cα` 与 `z` 两路速度场。【核实：§3.3 / App. C】 |
| 耦合双时间 | 坐标走 `t_x`、隐变量走 `t_z`，两条时间轴各自调度，但共享同一个主干。【核实：§3.3】 |
| Euler–Maruyama | 在概率流 ODE 上加噪声项转成 SDE 采样，`η` 控制噪声强度。【核实：App. E.1】 |
| indexed / unindexed motif | motif 是否告知其在生成序列中的**位置**。unindexed 只给结构、不给位置，需要模型自己找位置。【核实：§3.5 / App. B】 |
| all-atom / tip-atom motif | motif 条件是全部原子还是只给 tip 原子（侧链末端），后者更接近真实设计场景。【核实：§3.5】 |
| co-designability | 采样出的骨架经 ProteinMPNN 逆折叠、再用 ESMFold 重折叠后仍回到原结构的比例。测的是"这对（结构, 序列）是否自洽"。 【核实：§4】 |
| designability | 与上一条常被混用；本篇统一按论文口径写成"co-designability（8 条 MPNN 序列，best-of-8）"。【推断：按论文评测协议描述】 |

## 3. 原理与推导

### 3.1 变量分解：为什么必须留一个显式锚

论文的联合分布分解（§3.1）：

```text
p_θ,φ(x_Cα, x_¬Cα, s, z) = p_θ(x_Cα, z) · p_φ(x_¬Cα, s | x_Cα, z)

p_θ   ：流匹配主干（可学习，生成 x_Cα 与 z）
p_φ   ：VAE 解码器（可学习，条件于 x_Cα 与 z 解出侧链与序列）
q_ψ   ：VAE 编码器（仅训练时使用）
```

**这个分解的关键不在公式，而在"谁没有进隐空间"**：Cα 被显式保留在生成侧。作者做了一个直接消融来证明这不是随意选择——把 Cα 也编码进 8 维 latent（全潜变量），all-atom co-designability 从 **83.8% 掉到 21.2%**。【核实：附录消融】

物理解释：8 维对"一个残基的全部几何"是严重的瓶颈。如果连 Cα 位置都要从 8 维里恢复，解码器就同时在承担"定位"和"补细节"两件事，误差会互相放大；把定位留给显式坐标、让隐变量只管残基身份与局部构象，瓶颈压力就小得多。【推断：基于消融结果的机制解释】

这也解释了为什么它不能叫"全潜变量模型"：生成端仍有 3 维/残基的显式几何。

### 3.2 VAE：β = 1e-4，且对 β 不敏感

- 训练目标为标准 ELBO，先验取各向同性高斯 `N(0, I)`，KL 权重 **β = 10⁻⁴**，并在 `{10⁻³, 10⁻⁴, 10⁻⁵}` 上做过扫描。【核实：§3.2.1 + 附录】
- 取这么小的 β 是刻意的：隐变量要尽量保留几何信息，宁可牺牲先验匹配度。后验一旦被压得太接近标准正态，解码器就丢细节；而流匹配阶段只需要一个"可采样的、够光滑的"隐空间，不需要它严格是 N(0,I)。【推断：基于 β 量级与设计意图】
- 编码器与解码器各约 **130M 参数、12 层 transformer**。【核实：§3.2.1 / App. C.2.1】注意：附录另一处写 14 层，与 12 层口径**不一致**，本篇并列记录，不强行二选一。【核实：正文与附录口径冲突】
- 训练分三段（长度上限逐步放开），EMA 0.999，lr 1e-4，wd 0.01：

| 阶段 | 长度上限 | 步数 | 硬件 |
| --- | --- | --- | --- |
| 1 | 32–256 | 500k | 16×A100-80GB |
| 2 | 32–512 | 140k | 32×A100 |
| 3 | 32–896 | 180k | 32×A100 |

【核实：App. C.2.1】

### 3.3 流匹配主干：双路速度场，主模型关掉三角更新

- denoiser **160M 参数、16 个 block**，同时输出 `v_Cα`（3 维）与 `v_z`（8 维）两路速度。【核实：§3.3 / App. C】
- 注意力带 pair bias；**三角乘法更新在主模型中不启用**，只作为可选变体（tri）存在。这与 Proteina 的 M_FS / M_no-tri 取舍一脉相承：作者倾向于用数据规模换掉昂贵几何归纳偏置。【核实：§3.3】
- 训练目标是两路速度回归之和；时间采样不是均匀的，而是"少量均匀 + 主体 Beta"：

```text
t_x ~ 0.02 · U[0,1] + 0.98 · Beta(1.9, 1)     # 偏向 t 靠近 1（干净端）
t_z ~ 0.02 · U[0,1] + 0.98 · Beta(1, 1.5)     # 偏向 t 靠近 0（噪声端）
```

【核实：App. E】

- **训练的时间采样分布与推理的离散调度不是同一套**。跨模型比较步数时这一点常被读错。【核实：App. E.1】

### 3.4 采样：400 步 Euler–Maruyama，两条时间轴各自的 β 调度

采样在两条耦合 SDE 上做 Euler–Maruyama【核实：App. E.1】：

```text
N = 400 个积分步
η_x = η_z = 0.1                     # 噪声强度
β_x(t_x) = 1 / t_x
β_z(t_z) = (π/2) · tan( (π/2) · (1 − t_z) )

离散时间网格：
t_x[n] = (1 − 10^(−2n/N)) / (1 − 10^(−2))
t_z[n] = (n / N)^2
```

三个可以直接拿来对比的结论：

1. **步数是 400，不是 1000**，且论文正文明确写了 "For all our experiments we use N = 400 integration steps"。【核实：App. E.1】
2. **σ 调度不是 EDM 那套**。这里没有 `σ_max / σ_min / ρ`，而是用 `β(t)` 的形状控制"哪一端加多少噪声"：坐标端 `1/t` 在 t→0 时发散（噪声端噪声大），隐变量端 `tan` 在 t→1 附近发散（干净端反而要更强噪声来跨模态）。与 AF3 的 EDM x0 参数化不可直接比较。【核实：公式；对照为推断】
3. **两条时间轴的推进速度不同**：`t_z = (n/N)²` 是二次的，前期慢后期快；`t_x` 是指数式的。等于让隐变量先"想清楚"再快速定稿，坐标则相反。【推断：基于网格形状】

解码端（§3.4）：坐标取**均值**、序列取 **argmax**，一步完成，非自回归。

### 3.5 条件接口：只有 motif，且分四组

| 条件 | 形式 | 说明 | 标记 |
| --- | --- | --- | --- |
| 无条件 | 无输入 | 主结果（68.4% / 75.0% / 93.8%）都在这一档 | 【核实：§4】 |
| indexed all-atom motif | 给定 motif 的原子坐标 + 序列位置 | 最"好做"的一档 | 【核实：§3.5】 |
| indexed tip-atom motif | 只给侧链末端原子 + 位置 | 更接近真实设计信息量 | 【核实：§3.5】 |
| unindexed all-atom motif | 给原子坐标，不给位置 | 需要模型自己搜索放置位置 | 【核实：§3.5】 |

- **没有 contig、没有链组成、没有表位、没有 MSA、没有模板、没有能量项**。复合物条件能力不在本篇，在 Proteina-Complexa。【核实：两篇 §3 对照】
- motif 训练集是独立的 Foldseek 簇，约束为"最大长度 356、最低 pLDDT 80"。【核实：App. B】
- 四组 motif checkpoint 的训练预算不同：indexed all-atom 150k 步 / 64×A100；indexed tip-atom 120k 步 / 128×A100；unindexed 650k 步 / 32×A100。【核实：App. C】

### 3.6 "是否依赖外部折叠模型"——否定证据

这是仓库第二个易错点。结论：**不依赖**。三条证据：

1. **监督信号**：训练目标只有 VAE 的 ELBO（重建 + KL）与流匹配的速度回归，没有任何折叠模型输出参与损失。AFDB 结构本身是 AF2 预测的，但那是**数据来源**，不是训练时的在线监督。【核实：§3.2 / §3.3 目标函数】
2. **自洽（self-consistency）**：论文没有 self-consistency 训练环节。所谓"自洽"出现在评测：ProteinMPNN 逆折叠 + ESMFold 重折叠，算 scRMSD，这是**评估协议**不是训练项。【核实：§4 评测协议】
3. **代码侧**：仓库中 ESMFold 与 ProteinMPNN 只出现在 metrics / evaluation 路径，不在 training 路径。【代码／配置核实：README 与仓库结构】

一个必须写清的细节：**训练数据是 AF2 预测结构，不是实验结构**。这带来一个隐性偏置——模型学到的是"AF2 会输出的那种几何"，而不是"实验解析出的那种几何"。作者用 pLDDT ≥80 过滤来压低这一偏置，但没有给出"在 PDB 实验结构上微调"的对照。用它的坐标做下游物理计算（如 Rosetta 打分、对接）时，这个偏置值得单独验。【推断 + 核实：数据来源为核实，偏置影响为推断】

### 3.7 与 Proteina 的对照

| 维度 | Proteina | La-Proteina |
| --- | --- | --- |
| 生成变量 | `x ∈ R^{3L}`（仅 Cα） | `x_Cα ∈ R^{L×3}` + `z ∈ R^{L×8}` |
| 序列 | 不生成，外挂 ProteinMPNN | 解码器直接输出 20 类身份 |
| 侧链/非 Cα 原子 | 不生成 | 解码器输出 `R^{L×36×3}` |
| 隐变量 | 无 | 8 维/残基 |
| 主干 | 15/18 层，208M/397M | 16 block，160M |
| 三角更新 | M_FS 用，M_no-tri 不用 | 主模型不用，可选 tri 变体 |
| 采样 | rectified flow，400 步 EM SDE | 部分潜变量耦合双时间，400 步 EM SDE |
| 条件 | CATH 折叠类 + motif | 无 / motif（四组） |
| 卖点 | 容量与数据规模 | 全原子 + 序列联合生成 |

【核实：两篇 §3 与 Table】

**一句话**：Proteina 把"主链形状"这一件事做到极致；La-Proteina 把"一条完整分子（原子 + 序列）"压进同一个生成过程，代价是必须引入 VAE 与两阶段训练。

## 4. 训练数据构成与切分

- **数据源与规模**：AFDB（AlphaFold DB）的 Foldseek 簇代表结构，**全部为 AF2 预测结构，不含实验 PDB**。【核实：§3.1】
  - 主线子集：pLDDT ≥ 80、长度 32–512 aa（另有 β 折叠比例过滤），过滤后约 **3.5×10⁵** 条。【核实：§3.1 / App. M】
  - 长蛋白子集：pLDDT ≥ 70、长度 384–896 aa，共 **46,942,694** 条 → MMseqs2 50% 聚类 → **4,035,594** 簇；训练时按簇采样，最多用到约 46M 结构-序列对。【核实：App. M】
  - motif 训练集：独立 Foldseek 簇，最大长度 356，最低 pLDDT 80。【核实：App. B】
- **清洗与去重**：pLDDT 阈值 + 长度区间 + Foldseek 簇代表 + MMseqs2 50% 序列同一性聚类；长蛋白子集额外按簇均匀采样以避免长链被短链淹没。【核实：App. M】
- **切分与泄漏控制**：**作者未说明**。已查正文 §3.1、App. M.2 与全部训练细节附录，未见 held-out 生成测试集、时间切分或与评测集隔离的陈述；novelty 指标用的是"与 PDB / 与 D_FS 的最大 TM-score"，属于事后度量而非切分保证。【未核实：已查上述三处，属"作者没写"】
  - 一个具体风险：co-designability 用 ESMFold 重折叠评估，而 ESMFold 的训练集与 AFDB 高度重叠；如果生成样本落在 AFDB 已见区域，评估会偏乐观。论文的 novelty 数字（vs PDB 0.75 / vs AFDB 0.82）说明样本确实较新，但没有做"训练集成员 vs 非成员"的分层评估。【推断】
- **覆盖与偏置**：单体为主；长度覆盖 32–896 aa；二级结构分布偏 α（α 72%、β 5%），说明 β 富集结构仍是被压制的少数类。【核实：§4 二级结构统计】物种/构象偏置未讨论。【未核实】
- **可获取性与许可**：数据本身来自公开 AFDB，可复现；代码 Apache 风格未明示（**未核实**）；权重在 NGC，许可随模型卡；训练需数十张 A100 量级。【核实 + 未核实：分项标注】

## 6. 实践与应用

- **适用场景**：单体从头设计（长度 32–896 aa）；原子级 motif 脚手架（给定结合位点/催化位点的原子几何）；需要"直接拿到序列 + 侧链"而不想外挂逆折叠的流程。
- **不适用**：binder 设计（无靶标条件接口）、复合物、需要 contig/链指定的任务、需要置信度打分的筛选（**它没有 pLDDT/PAE 头**，必须外挂 ESMFold/AF2 评估）。【核实：无 confidence head；对照为推断】
- **checkpoint 选择**（LD1–LD6）：

| 编号 | 用途 |
| --- | --- |
| LD1 / LD2 | 无条件，非 tri / tri 变体 |
| LD3 | 长蛋白（≤896 aa） |
| LD4 | indexed all-atom motif |
| LD5 | indexed tip-atom motif |
| LD6 | unindexed all-atom motif |

【核实：README / NGC 模型卡】

- **关键参数**：`N=400`（降步数会掉质量，论文无步数消融，**不要**照搬 Proteina 的少步经验）；`η=0.1`；motif 任务优先试 indexed（成功率更高），只有在"位置未知"的真实场景才用 unindexed，且要接受更高失败率。
- **成本提示**：400 步 × 160M 主干，单条 300 aa 样本在单卡上是秒级到十秒级；批量筛选建议先小步数粗筛再全步精修（**该策略论文未验证，属工程推断**）。

## 7. 疑问与讨论

- **Q**：它和 Proteina 是同一批人吗？
  - **A**：是。Geffner 为两篇共同一作，Kreis / Vahdat 共同通讯，团队为 NVIDIA GenAIR。但模型不是"Proteina 加个解码器"——变量分解、训练流程（两阶段 VAE + FM）、采样器都换了。【核实：两篇作者列表】
- **Q**：既然隐变量只有 8 维，为什么能装下 36 个原子？
  - **A**：装不下"精确坐标"，装的是"残基类型 + 局部构象的低维流形坐标"。Cα 已给出全局定位，残基内的原子排布在键长键角约束下自由度远小于 108；加上解码器是非线性映射，8 维足够表达常见残基构象。但这也意味着**罕见构象/非标准残基的表达能力受限**——论文没有单独测这一项。【推断 + 核实：维度为核实，能力边界为推断】
- **Q**：训练集是 AF2 结构，会不会把 AF2 的系统性误差学进去？
  - **A**：会，且论文未做 PDB 微调对照。这是用它做物理计算前必须自己验的一条。【推断】
- **Q**：为什么论文里同一处层数写 12、另一处写 14？
  - **A**：口径冲突，未给出解释。写对比表时应标注"12–14"，不要单写一个数。【核实：冲突存在】
- **Q**：400 步是不是过采样？
  - **A**：论文没有步数-质量曲线，无法判断。这是本篇最实在的一个空白。【核实：缺失】

## 8. 学习心得

- **"部分潜变量"不是一个修辞，而是一个可量化的设计约束**：8 维 vs 显式 Cα 的分工，由 83.8 → 21.2 的消融直接钉死。以后看到任何"latent + 解码"的模型，第一件事应该问"哪些自由度没进 latent"。
- 判断一个模型"是否全原子"，不能只看输出，要看**生成端的自由度**。La-Proteina 输出全原子，但生成端是 3+8 维/残基；RFD4-Proteina 输出全原子，生成端是 3+32 维/残基。这两者与"逐原子扩散"（如 SeedProteo 的 atom14、AF3 的 token 化原子）在计算性质上完全不同类。
- 隐变量维度是最容易被"记住又记错"的数字，因为它不进入任何公式推导，只出现在一句话里。写笔记时应当连同**出处行**一起记，否则下一代模型一出现就会串。
- 这篇也提醒：**"用了折叠模型"要分清三种用法**——数据来源（AF2 生成 AFDB）、训练监督（本篇没有）、评测（ESMFold 重折叠）。三者混为一谈是仓库此前出错的根源。
